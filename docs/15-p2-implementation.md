# P2 分步实现

开始日期：2026-09-24。P2 按可独立验收的纵向步骤推进；本页记录实际实现与尚待验证的边界，不把编译通过视为整阶段通过。

## P2-01：养成规则、存档与设置面板

已实现：

- `pet-core::care` 负责饱食、精力、心情、亲密度、食物库存和喂食／玩耍／休息的纯规则。需求值限定在 0–100；玩耍消耗 10 精力，冷却 10 分钟；初始食物 3 份，新 UTC 自然日将库存补足至 3 份。
- `pet-persistence` 是 SQLite 单连接写入端。第一次打开创建 `schema_migrations`、`pet_state`、`inventory`、`care_events` 和 `settings`。一次成功操作在同一事务内提交需求值、库存和 `request_id`；重复 ID + 同动作只返回当前状态，重复 ID + 不同动作拒绝。动画尚未接入，提交不依赖宿主成功。
- 应用数据目录中的 `care.sqlite3` 独立于角色包与旧版 JSON 设置。设置面板可查看状态、执行三项操作；宿主断开或语音／LLM 不存在时仍可使用。运行中以启动时 UTC 锚点加单调时间推进；重新启动后读取 UTC 差值，回拨不倒扣需求值，过长间隔按 24 小时计算，并保留不足一小时的余量。回拨时将未来的玩耍冷却重置为从当前时刻起 10 分钟，避免长期锁死。
- 本步骤没有把照料动作映射到模型动画，也没有实现行为状态机、招呼／探头／邀请、短时占屏及免打扰；它们属于后续 P2 步骤。

验证：`cargo test --offline -p desktop-pet -p pet-core -p pet-persistence` 通过。存档测试涵盖重复喂食跨重启、同 ID 冲突、失败操作回滚、24 小时离线封顶、时钟回拨、频繁读取的衰减余量、玩耍冷却和跨日库存补充。现阶段未完成真实桌面点按与异常断电测试；SQLite 事务测试只证明进程重开后的提交状态。

## P2-02：活动仲裁与照料反馈

已实现：照料请求提交成功后，主程序向 PetCore 投递动作事件；重复请求不重播动作。喂食、玩耍、休息分别进入 3、4、8 秒的互斥活动，结束后回到待机或原吸附状态。拖拽、隐藏、停止当前互动可立即取消；拖拽中执行照料只更新存档，不抢走拖拽状态。停止操作可从设置面板和托盘发起。宿主断线不影响照料存档，恢复后不重播旧动作。100 次确定性照料／拖拽序列以及优先级测试已通过。

## P2-03：受限主动陪伴

已实现：主动陪伴默认关闭，可设置免打扰、最短间隔 1–60 分钟（默认 15 分钟）、每小时最多 1–4 次（默认 2 次）。精力低于 20 时不发起；按需求值选择招呼、探头或邀请，每次最多 4 秒。设置保存在同一 SQLite 数据库中。P2 专用 `feed`、`play`、`rest`、`greet`、`peek`、`invite` 表情在角色包中均为可选项；缺失时回退到现有头／身体反馈。传输协议版本升为 2，主程序与宿主需成对更新；旧角色包仍可导入。若角色包未提供独立表情，三种主动行为的画面可能相似，但界面活动状态不同。

此步尚未进行用户桌面验收。自动化测试覆盖间隔、每小时次数、免打扰、低精力、显式照料抢占、停止后重新计时与专用表情选择。

## P2-02／03 桌面测试交接

测试包：`artifacts/local/p2/DesktopPet P2 Care Companion.app`（本地签名、未包含第三方角色资源，首次运行会打开设置面板）。先从菜单栏退出旧桌宠，只运行此包。这个包使用新的应用身份，之前另一包的辅助功能授权不会继承；以下测试不需要开启他应用窗口吸附。

1. 在设置面板确认四项需求值和 3 份食物，点一次喂食；库存应减 1。点玩耍，再在 10 分钟内重复点玩耍；第二次应显示冷却提示。点休息，确认精力增加。
2. 在休息活动的 8 秒内点“停止当前互动”，或用菜单栏 Pet → 停止当前互动；活动应回到待机／吸附状态。再试一次动作中拖拽、隐藏再显示；不应卡在进食／休息状态。
3. 开启主动陪伴，把间隔临时设为 1 分钟，保持免打扰关闭。等待约 1 分钟，观察活动状态和角色表情；打开免打扰后不应继续发起，关闭后可再次等待。测试后建议恢复 15 分钟或关闭主动陪伴。
4. 从菜单栏正常退出并重开同一包；需求值、食物和主动陪伴设置应恢复。记录异常的操作、活动状态与大致时间；若角色视觉反馈难以区分，也请如实说明。

## P2-04：短时占屏（待桌面验收）

占屏默认关闭，需要同时开启主动陪伴及占屏。滚动一小时内的第二次主动行为会请求独立、非激活的透明角色窗口：原紧凑角色暂时隐藏，临时窗口出现在当前显示器工作区中央，另有小型原生关闭窗口。宿主独立执行 8 秒上限；主程序的停止、隐藏、免打扰和退出路径也会结束占屏。透明角色窗口保持鼠标穿透，关闭窗口和托盘可供手动停止。主程序或宿主异常退出时临时窗口随宿主关闭。

自动化测试覆盖核心的默认关闭、启动、到期及停止命令；宿主代码已构建并签名验证。尚需用户确认多屏位置、焦点、透明区域点击、关闭按钮、主程序卡住时的独立超时及原角色恢复，不能据代码路径宣布 P2 整体验收通过。

## 2026-09-25 表情适配检查

用户观察到当前默认只有眨眼。核查发现此前两个 P2 测试包引用的本地角色包仅配置 `head_pat` 和 `body_tap`，P2 六项专用动作未登记；此时照料／主动活动会回退到这两项表情。原模型也没有动作文件，因此尚无真正的进食、玩耍或探头肢体动画。待机原先只有程序化眨眼与视线。

请先退出其他 DesktopPet 测试包，再打开 P2 Actions：观察待机是否有轻微摆动；分别点击喂食、玩耍、休息，确认画面不再只剩眨眼；开启主动陪伴并将间隔设为 1 分钟，观察招呼与随后占屏（需另开启占屏）。请记录哪些表情在视觉上不符合文字标签，以及占屏是否在 8 秒内退出并恢复原位置。自动化测试无法代替这一步的视觉判断。

后续目视反馈要求摸头固定 `Shy`、摸脸在 `shy_normal` 与 `Wink` 间伪随机、摸手在 `Shy` 与 `Happy1` 间伪随机。角色包 v4 新增可选 `touch_variants`，只允许给已配置的脸和左右手区域选择已绑定提示；主程序在预览与真实点击中共用选择逻辑。头、脸、手的有效短按不再因普通表情冷却显示“表情 无”，但亲密度收益冷却、低需求时不增加亲密度及限制区第三次惩罚后的退避仍保留。更新后的角色包需重新导入，桌面外观仍待用户验收。
