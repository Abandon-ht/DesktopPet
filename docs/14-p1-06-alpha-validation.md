# P1-06 alpha 桌面验收

开始日期：2026-09-24。P1-02、P1-03 已通过用户桌面验收；P1-04 的动画、点击表情与可调视线范围已确认；P1-05 的坐窗位置、跟随与高度微调已确认，但跟随仍有可感知滞后。以下项目需要实际桌面结果及日志，不能用单元测试替代。

## 采集方法

先从菜单栏退出所有旧版，在项目根目录打开终端运行：

```sh
python3 tools/p1/run-p1-06.py --label idle
```

启动器默认运行固定的 `artifacts/local/p1/gaze-range/DesktopPet Gaze Range.app`，自动在被 Git 忽略的 `artifacts/local/p1/p1-06/` 下建立本次目录，保存 `app-stderr.log`、每 5 秒一次的 `resource-samples.csv`、包的哈希与版本信息，以及正常退出后更新的 `render-metrics.json`。每组测试可重新运行并更换 `--label`；结束时使用菜单栏 **Pet → 退出 DesktopPet**，让宿主写出最后的帧指标。不要同时启动多份桌宠，也不要在一次验收期间重建或重签测试包。

如需在已获辅助功能权限的坐窗包上做窗口测试，单独运行：

```sh
python3 tools/p1/run-p1-06.py --label window-snap --app 'artifacts/local/p1/ax-seated-snap/DesktopPet P1-05 Seated Snap.app'
```

这两包是不同的应用身份。坐窗包保留此前已授权的窗口功能；新视线包无需为普通视线/交互测试开启辅助功能权限。两次运行分别记录，不能把旧包的窗口结果当作新包的集成结果。

## 2026-09-24 实机结果与日志分析

用户已完成六项操作，反馈 02 的 100 次交互及 05 的外接屏测试正常；06 使用 Finder、Safari 和用户所写的 “TeitEdit” 编辑器，窗口跟随的可感知滞后持续存在。02 的 100 行清单依据这次汇总反馈标记为通过，但没有逐次操作时间或备注；该标记代表用户验收，不代表日志逐次验证。除跟随滞后外，用户未报告其他异常。

采集器在 `artifacts/local/p1/p1-06/` 留下四次会话；每次主程序均以退出码 0 结束。01、03、04 使用 Gaze Range 包，06 使用另一个已授权的 Seated Snap 包，因此两包的功能结果不能合并解释为同一发布包的完整集成验收。

四次 present 调用间隔 p95 均比 33.3 ms 目标高约 0.8–1.7 ms，严格按现有指标尚未达标；它不是实际屏幕帧率。CPU 绘制/提交 p95 仅约 2.5–5.5 ms，不能据此把窗口跟随滞后归因于渲染计算。空闲会话中宿主 CPU 采样中位数约 9.8%，RSS 基本稳定；窗口测试中宿主 CPU 中位数约 12.6%，RSS 从约 115 MB 到 131 MB。短时数据不足以推断长期能耗或内存泄漏。

06 的 3 次吸附后都记录了 `target_unavailable_or_focus_changed` 解除；另有 27 次拖拽释放记录为 `external_not_attached`。这些记录缺少事件时间戳、窗口应用名、具体拒绝/解除原因和每次跟随的位置差，无法判断三次解除是预期焦点切换还是目标跟踪不稳定，也无法计算跟随延迟。27 次未吸附并不等于 27 次预期吸附失败。05 的跨屏坐标有日志旁证，但拔插外屏和复位行为没有专门事件；02 的逐次结果同样只能依据用户反馈。

当前 AX 工作线程每次查询后休眠 250 ms，主事件循环也每 250 ms 才检查一次新快照。窗口刚移动后，几何变化可能分别等待这两个独立周期，常规情形下可累积到约 500 ms 再加 AX 查询和绘制时间；这是代码推断，现有日志尚不能实测确认。重复的可感知滞后应作为 P1-05/P1-06 未关闭问题处理。下一步先给窗口观察、角色位置更新和解除原因加单调时间戳诊断，再优先接入 AXObserver 的移动/缩放通知，保留低频查询作为不发通知应用的兜底，并在同一已授权测试包上复测延迟、误解除和能耗。动画帧间隔另行调优，不应与窗口跟随延迟混为一项。
