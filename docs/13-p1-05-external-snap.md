# P1-05 他应用窗口吸附

开始日期：2026-09-24。已加入实验开关和 macOS AX 前台窗口读取；实际吸附仍需获得辅助功能权限并做桌面验收。P1-04 的眨眼、视线和点击表情已获用户确认；100 次交互和多屏等仍待验收。

## 已完成的第一步

`apps/avatar-host-2d/src/external_snap.rs` 定义有身份的目标窗口和独立吸附状态。用户拖拽松开时，仅在角色脚底距合法目标顶边 12 逻辑点以内且水平范围重叠时吸附；记录沿目标窗口的水平比例，目标移动或缩放后可重算角色位置。自身进程、已最小化窗口、错误几何和未获授权均被拒绝。

目标丢失、窗口身份变化、最小化或授权撤销时立即清空吸附状态。上述策略由确定性单元测试覆盖。

## 实验接入

- 设置面板增加“他应用窗口吸附”开关，默认关闭。用户主动开启时宿主先读取 `AXIsProcessTrusted`；没有授权则调用 `AXIsProcessTrustedWithOptions` 请求系统显示授权提示，并拒绝本次开启。用户完成系统授权后需再次点击开关；屏幕底部吸附继续可用。
- 独立线程每 250 ms 读取当前前台应用的焦点窗口，只取进程、窗口身份、位置、大小和最小化状态；每次 AX 消息设置 0.2 秒超时。渲染线程读取最新快照，不直接执行 AX 查询。拖拽松开时按上述规则吸附，已吸附时按最新几何跟随。
- 手动关闭、隐藏、拖动角色会解除吸附；目标丢失、最小化或权限撤销时回落到当前工作区底部。焦点切换到另一应用窗口也会解除，因为当前版本只观察焦点窗口。
- 当前尚未接入 `AXObserver` 通知，采用 250 ms 查询；部分应用可能不提供焦点窗口或所需属性。尚未验证实际跟随精度、跨 Space 和性能，不能标记 P1-05 通过。

2026-09-24 的实际授权检查仍返回 `ax_trusted=false`：旧本地包把主程序和渲染宿主作为不同进程运行，且多个不同文件名的测试包共用同一个 `CFBundleIdentifier`。系统列表显示某个测试包“已开启”并不能证明当前运行的进程获权。文件选择器也不能可靠选择包内的裸宿主可执行文件。已将宿主改成独立的嵌套 `.app`，并给每个本地开发包生成独立标识与对应的宿主标识；外层和嵌套包按顺序做本地临时签名。此结构已通过签名校验及编译检查，但真正的 AX 授权和吸附仍待人工验收。

开发包使用临时签名。重建或重新签名可能改变系统用于识别授权对象的代码身份；一次人工验收期间应固定同一个包，不要在授权后重建。不要一次选择多个旧测试包。

## 后续实现顺序

1. 接入 `AXObserver` 移动、大小、最小化和销毁通知，以低频查询补足不发送通知的应用；稳定窗口身份与权限撤销后的 UI 状态。
2. 验证至少三类应用窗口，以及拒绝/撤销授权、关闭/最小化、Space 和多屏行为。结果写入此文档后才能标记 P1-05 通过。

当前可复现的检查：

```sh
cargo test -p avatar-host-2d -p desktop-pet --locked

python3 tools/p1/verify-hidden-host.py target/release/avatar-host-2d artifacts/local/p1/nahida-motion-pack/manifest.json
```

实际验收时，先退出所有旧版，只打开 `artifacts/local/p1/ax-permission-test/DesktopPet P1-05 Permission Test.app`。它在启动时显示设置面板。点击实验开关以触发系统提示；在 macOS“系统设置 → 隐私与安全性 → 设备控制和数据访问”（旧系统可能名为“辅助功能”）仅允许 **DesktopPet P1-05 Permission Test** 和系统实际列出的 **DesktopPet P1-05 Permission Test Host**。如果需要手动添加宿主，它在测试包的 `Contents/Helpers/DesktopPet Avatar Host.app`。完全退出桌宠后从同一路径重新打开，再次点击实验开关并等待它是否保持选中。然后将角色脚底拖到另一个应用窗口上边缘约 12 逻辑点内，移动、缩放、最小化及关闭目标窗口并记录结果。授权对象和实际响应需在本机确认；没有授权时无需重复点击开关。
