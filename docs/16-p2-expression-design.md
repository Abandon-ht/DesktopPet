# P2 表情编排设计与实施

日期：2026-09-28。用户目标：让养成数值和交互选择表情，覆盖本地角色包中的全部 13 个 `exp3.json` 文件；修正切换角色后仍显示“正在尝试切换角色…”的 UI 状态。下文保留实施前的现状分析与设计依据；代码和本地测试包现已完成，阈值和角色语义仍待桌面目视验收。

当前设置面板已移除验收阶段的“表情检查”区。下文有关逐项预览的步骤是历史测试记录；正式交互由养成状态和角色实际点击驱动。

## 已核实的现状

- 原始 `model3.json` 的 `FileReferences` 没有 Motion 组，13 个表情文件通过参数变化实现面部、右手前后层次等效果。`HandChange` 修改 `Param17`，CDI 名称为“右手手前”；它不是连续手臂动作文件。
- 当前 P2 本地包只用 6 个不同表情文件填充 8 个动作入口；`Sad2` 与 `black` 的参数和值完全相同，所以 13 个文件只有 12 种不同的参数组合。无法仅靠规则让这两份文件呈现不同画面。
- PetCore 已接收 `Needs` 并仲裁 `Activity`，但仅在互动开始时发送一次 `PlayFeedback`；需求数值不驱动持续表情。宿主每帧重置参数，只播放至多一个短时 `ExpressionPlayer`，结束后回到中性姿态。眨眼、视线和身体轻摆是独立的程序化参数。
- 角色包 v1 的 `actions` 最多表达 8 个语义动作，每项仅可引用一个表情；没有完整表情目录、基础状态或多阶段反馈。现有 UI 无 13 项逐个预览入口。
- `import_pack`／`select_pack` 返回的是“已接受切换请求”。主程序的 `status.detail` 后来已经写入“角色切换完成”，但 `#import-message` 在 JS 中被设置为“正在尝试切换角色…”后只在失败或再次操作时改变，未订阅切换结果。下拉列表也没有依据当前实际 `active` 路径初始化。

## 状态和动作的初版映射

下表是语义候选，不按文件名推断最终视觉意义。基础状态只选一个，短时反馈会临时盖过它；基础状态随后恢复。阈值为百分制的进入值，退出时留约 5 点回差；普通状态至少保持 10 秒，严重饥饿或精力耗尽可立即切换。

| 文件 | 已核实的参数效果 | 拟定触发入口 |
| --- | --- | --- |
| `Angry` | 眉形、嘴形偏负面 | 饱食 ≤30 且心情 ≤35 的易烦躁基础状态 |
| `Halfeyes` | `Param24` 半目 | 精力 ≤35 的困倦基础状态；休息反馈 |
| `HandChange` | `Param17` 右手手前 | 主动招呼；手部变化的专门验收项 |
| `Happy1` | 笑眼、眉形、嘴形 | 心情 ≥80 且饱食、精力均 ≥40 的愉快基础状态；喂食完成 |
| `Sad1` | 眉形、嘴形偏低落 | 心情 ≤35 的低落基础状态 |
| `Sad2` | `ParamPale` 苍白 | 精力 ≤15 的严重疲惫基础状态 |
| `Shy` | `ParamCheek` 脸颊 | 亲密 ≥70 且心情 ≥60 的亲昵基础状态；邀请和高亲密触碰 |
| `StarEye` | `Param15` 星眼 | 玩耍中的短时反馈 |
| `Wink` | 单侧闭眼及笑意 | 主动探头的短时反馈 |
| `black` | 与 `Sad2` 完全相同的 `ParamPale` | 饱食 ≤15 的严重饥饿基础状态；UI 标明与 `Sad2` 同效 |
| `kusa` | `Param16` 草元素效果 | 玩耍成功且心情达到 ≥80 时的短时庆祝，设冷却避免频闪 |
| `mouthchange` | `Param25` 嘴部样式 | 喂食开始阶段，再过渡到 `Happy1` |
| `shy_normal` | `ParamCheek2` 从默认 1 降至 0 | 普通、中性基础状态；与 `Shy` 切换时检查脸颊连续性 |

基础状态优先级：严重饥饿 → 严重疲惫 → 易烦躁 → 困倦 → 低落 → 亲昵 → 愉快 → 中性。若两种严重需求同时成立，先按上述顺序呈现，设置面板仍显示全部数值。所有数值只是选表情的输入，不改变现有衰减、库存或冷却规则。`kusa`、`mouthchange` 和 `shy_normal` 的实际观感仍需用户确认；不合适时调整语义映射，而不是改动原始资产。

交互优先级：停止／隐藏／拖拽取消短时反馈；成功的显式照料高于主动招呼；头部和身体触碰高于待机；免打扰只阻止主动行为，不冻结数值驱动的基础表情。失败的照料请求先显示现有规则错误，不伪装成已完成动作。重复 `request_id` 不重复播表情。占屏只使用当前可用语义反馈，8 秒独立超时规则不变。

## 契约与编排

1. **PetCore 只输出语义。**增加 `BaselineExpression`（如 `neutral`、`cheerful`、`tired`、`critical_hunger`）和必要的短时 `Reaction`；由纯函数从 `Needs` 与事件算出，缓存上一次选择，仅变化时发命令。初始化、切换角色、宿主重连时重发当前基础状态。角色专有参数 ID 和文件名不进入 PetCore。
2. **角色包登记完整目录。**新包格式列出 `expressions` 目录（稳定 ID、相对路径、供诊断使用的标签）及语义 `bindings`；动作可包含按时间排列的 1–3 个反馈阶段。导入时检查路径仍在包内、文件可解析、参数 ID 存在、时长和目录大小有界。13 个文件都可逐个预览；`Sad2`／`black` 的重复参数给出提示，不拒绝导入。旧 v1 包仍可导入，缺失状态槽回退中性，旧动作槽继续工作。新格式及主宿主协议一起升版，文档和 demo 模板同步更新。
3. **宿主统一编排。**保留一个持续基础表情、至多一个有期限的短时反馈；短时反馈结束后恢复最新基础表情。Mocari 0.3.1 的 `ExpressionManager` 已支持旧表情淡出和新表情淡入，可优先复用并验证其叠加顺序；每帧仍以默认参数为起点，接着施加视线／轻摆、表情，再处理眨眼的参数所有权。`Wink` 等占用眼睛参数的表情须避免自动眨眼覆盖；未来语音口型优先级高于嘴部表情。停止、拖拽、隐藏和切换角色后不残留旧表情。
4. **展示与诊断。**设置面板显示“当前角色”和基础表情语义；本地诊断区提供 13 项逐个预览与回到自动模式，不改变养成存档。正常用户操作仍由状态和互动触发，不靠手动轮播。诊断入口只引用当前已导入角色包，缺项显示“此角色不支持”。

## 切换提示的先行修复

`import_pack`／`select_pack` 应返回本次请求的递增 `selection_id`。状态查询同时返回 `requested_pack`、`active_pack`、该 ID 的 `pending | succeeded | failed` 和失败原因；宿主握手及角色替换完成后才写 `succeeded`。UI 按匹配的 ID 把“正在尝试切换角色…”收束为“已切换到 …”，失败时显示原因并标明仍在使用的角色；其他全局 `ready` 或显示／隐藏状态不得误判为本次切换成功。重开设置窗口时以 `active_pack` 设置下拉选中项，取消永久停留的旧提示。此修复可作为表情编排前的独立小步骤。

## 分步实现与验收

1. **P2-05a：切换反馈。**先改状态查询和 UI，同一包重复切换、候选包损坏、快速连续切换、宿主重启均能正确显示最后一次请求的结果；保留旧角色的失败路径仍可用。
2. **P2-05b：目录与预览。**扩展包格式和校验，确认 13 项都能按名称逐个加载，重复 `Sad2`／`black` 被识别；旧 v1 包不报错。使用本地角色资源测试，但不提交角色文件。
3. **P2-05c：状态基础表情。**实现纯映射、阈值回差、最短保持时间和重连同步。测试边界值、同时低需求、快速数值变化、离线恢复及旧包回退。
4. **P2-05d：互动反馈与宿主过渡。**接入喂食两阶段、玩耍庆祝、休息、主动行为和点击；测试打断、超时、眨眼所有权、重复请求及 100 个可重复状态序列。
5. **桌面目视验收。**交给用户逐项查看 13 个文件、八类基础状态、互动反馈和明暗背景；尤其确认右手、草元素、嘴部、脸颊以及两份同效苍白表情。性能与切屏／隐藏后的恢复单列记录。目视结果确定最终语义映射，再关闭 P2 这部分验收。

本方案仅新增语义到已有表情参数的映射，不承诺模型拥有不存在的连续肢体动作；若希望真正的进食、挥手或睡觉动作，需要对应 Motion／源工程资产及单独适配。
