# AX650 端侧实现与测试计划

2026-10-10 从 `codex/linux-x11-baseline` 创建 `ax650` 分支。目标是让无通用着色器 GPU 的 AX650N 板卡独立运行二维桌宠和养成逻辑；复用已有角色宿主、协议和 Rust 核心，以软件 OpenGL 为默认渲染路径。稳定 30 fps 不作为本阶段验收条件。构建与交付入口见 [AX650 构建说明](../BUILDING.ax650.zh-CN.md)。

## 环境与已有证据

| 项目 | 2026-10-08 至 2026-10-09 实机记录 |
| --- | --- |
| 板卡 / CPU | AX650N，8 核 Cortex-A55，1.7 GHz，aarch64 / NEON |
| 系统 | Ubuntu 22.04、厂商 Linux 5.15.73，系统可见内存约 3.8 GiB |
| 桌面 | XFCE / xfwm4，Xorg / fbdev，单屏 1920×1080 |
| 图形执行 | 没有发现 `/dev/dri/renderD*` 或通用着色器 GPU；Mesa llvmpipe 在 CPU 上执行图形工作 |
| 用户已确认 | 私有诊断包的软件 OpenGL 路径可见角色；实际输出窗口 320×384 |
| 日志佐证 | 两次 30 秒运行正常退出；最新一次初始化约 201 ms，599 次 present 调用，调用间隔 p95 约 51.39 ms；离屏角色和自身窗口 pixmap 均有有效像素及部分透明像素 |

约每秒 20 次 present 调用是这一角色、尺寸和环境下的调用统计，不是显示扫描帧率，也不代表整个应用的性能。用户目视确认与像素证据共同证明当时的私有 GL 渲染路径可用；养成、存档、完整设置界面、语音以及本分支新主程序尚不能继承这次确认。

早期失败有三个独立原因或范围：

1. 缺少动态加载的 `libxkbcommon-x11` 及其 `libxcb-xkb` 依赖，宿主在 X11 初始化时退出。仅使用 `ldd` 检查直接链接依赖会遗漏此类库。
2. Vulkan 能初始化设备和模型、调用 submit/present，但用户看不到角色；当时没有有效像素回读，具体绘制、呈现或合成原因仍未定位。已确认窗口在正确的 X11 会话与屏幕范围内。`DISPLAY` 是 X 会话编号，不能从物理 HDMI 端口编号推导。
3. 首次 GL 运行被透明策略拒绝：锁定的 wgpu-hal 30.0.1 GLES 后端只报告 `Opaque`，原策略没有此后端的透明兼容入口。私有补丁在确认真实 32 位 ARGB visual 和合成器 owner 后允许 GL 兼容路径，并保留预乘 alpha；用户随后确认显示成功。

板卡上的 DRM card 和 framebuffer 是显示设备，不足以说明可执行 wgpu 着色器。AXERA NPU、IVPS 和 VO 各有专门用途，也不自动替代 Live2D 网格、遮罩和桌面合成。

## 第一阶段实现

第一阶段保留独立渲染进程，增加 `apps/ax650` 的 `desktop-pet-ax650` 主程序。它复用 `pet-ipc`、`PetCore` 和 `CareStore`，在板端持有养成状态、SQLite 存档、IPC 心跳与子进程生命周期。控制入口是同一终端的文字命令；主程序与宿主通过已有协议交互，不通过 IPC 传像素。

| 组成 | 第一阶段职责 |
| --- | --- |
| `desktop-pet-ax650` | 加载角色与存档，启动宿主，处理文字命令和角色事件，维持心跳，保存养成状态，正常或异常关停 |
| `avatar-host-2d` | Mocari 模型与表情、软件 GL、透明置顶窗口、X11 点击穿透与拖拽、屏幕位置及渲染统计 |
| `PetCore` / `CareStore` | 复用现有养成规则、行为仲裁与 SQLite 事务；动画结果不重复执行养成收益 |
| `tools/ax650` | 同版本 Ubuntu ARM64 构建、两程序及私有资源打包、动态依赖预检、独立运行日志 |

默认采用 `WGPU_BACKEND=gl` 和 `LIBGL_ALWAYS_SOFTWARE=1`，GL 透明兼容只在显式开启 `DESKTOPPET_X11_GL_ALPHA=1`、实际 GL 后端、surface 支持 `Opaque`、窗口深度为 32、XRender alpha 通道有效且合成器 selection 有 owner 时成立。普通 PreMultiplied / PostMultiplied 路径仍优先；NVIDIA Vulkan 例外独立保留。日志记录能力和原生透明证据，缺少条件时报错，不把不可见窗口当作成功。

帧调度可通过 `--fps` 调整，默认以 20 fps 作为本板的起点；这是请求的调度上限，不保证实际呈现频率。先使用 `--scale 64` 的 320×384 窗口。Vulkan 仅用于显式诊断，不能因接口查询成功而提升为推荐路径。

首阶段不依赖 Tauri WebView / WebKitGTK、托盘、语音、模型推理或外部服务。它不是完整桌面应用在 ARM64 上的移植声明，也不将此前 Linux x86_64 的界面验收扩大到 AX650。

## 运行与数据边界

包内提供两个 ARM64 程序、`run.sh`、资源、私有依赖及版权信息。`data/` 保留本包独立 SQLite 存档；`logs/` 为每次运行建立独立目录。复制新版本时保留旧包和存档，先用新目录验收，不覆盖此前用户测试包。

角色素材、模型权重、存档、日志和发布产物留在 Git 忽略位置。公开文档记录硬件和结果范围，不收录用户路径、主机地址、凭证或角色资源。编译不需要导入素材；运行包只复制显式指定的有效角色包，不扫描用户资源目录。

```sh
./run.sh --check-only
./run.sh --seconds 120 --scale 64 --fps 20
```

构建工具检查 ELF 架构、glibc 要求及直接链接依赖；包内 `--check-only` 检查运行时动态加载的库及符号，不连接显示或启动角色窗口。两者不能证明模型和透明桌面显示通过。正常运行需连接既有 X11 会话并拥有访问权限。交互命令为 `status`、`feed`、`play`、`rest`、`stop`、`show`、`hide`、`scale`、`expr`、`reset`、`quit`；具体参数见包内帮助及[构建文档](../BUILDING.ax650.zh-CN.md#用户手动测试)。

## 验收边界与交接

2026-10-10 第一阶段已在仓库提供的 Ubuntu 22.04 ARM64 Dockerfile 环境中验证：Rust 1.95.0、锁定 Cargo 依赖的两程序 release 构建通过；CLI 所需最高 GLIBC 为 2.34、角色宿主为 2.35，直接链接依赖解析通过。81 项 Rust 回归、16 项 Python 3.10 工具回归和主程序 / 宿主 / IPC 的严格 Clippy 均通过，格式与 shell 语法检查通过。

这些自动检查没有连接桌面或加载真实角色：主程序集成使用模拟宿主验证幂等、点击去重、存档恢复、日志收集、EOF、信号关闭、单实例及故障回收；工具验证架构、GLIBC、资源引用与私有库边界。当前包的真实渲染和交互仍由用户验证，不能以历史私有包的显示成功替代。源码提交和包内文件摘要记录在 `package-manifest.json` / `SHA256SUMS.txt`。

| 检查 | 结果与责任边界 |
| --- | --- |
| 既有私有 GL 角色显示 | 2026-10-09 用户确认通过；这是历史包结果 |
| 第一阶段 ARM64 编译 / 自动回归 | 2026-10-10 在标准 Ubuntu 22.04 ARM64 构建环境通过；97 项 Rust / Python 回归及严格 Clippy 通过 |
| 当前包角色、透明、输入、养成与重启 | 由用户在板端真实 HDMI 桌面手动测试，结果按新包记录 |
| 长时间性能与温度 | 记录呈现调用间隔、CPU、RSS、温度和异常；无稳定 30 fps 要求 |
| Vulkan、完整界面、音频 / NPU、Wayland | 本阶段没有可用性验收结论 |

不安装 VNC，不以 Remote Desktop 代替板端桌面验证，也不自动改变显示服务、驱动、合成器或 CPU governor。编译和不启动窗口的自动检查完成后，将包路径、摘要、运行命令及手动清单交给用户。
